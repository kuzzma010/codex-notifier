# Отчёт проверки Codex Notifier на macOS

Дата: 15 сентября 2026 г.  
Использовалась изолированная тестовая задача без изменения пользовательских файлов.

## Подтверждено фактически

- Финальный подписанный бинарник вернул `trusted` для Accessibility.
- `Build.command` собрал universal Mach-O (`arm64` + `x86_64`), проверил `Info.plist` и ad-hoc подпись; результат встроенных тестов: `PASS: 22 core checks`.
- Дополнительный monitor probe получил `task_complete` после дописывания уже открытого `.jsonl` менее чем за 0,8 с.
- Дополнительный reply probe подтвердил запрет записи не в редактор, запрет перезаписи существующего текста и распознавание пустого ProseMirror с placeholder.
- Реальное завершение тестовой задачи вызвало компактную карточку Notifier. Карточка раскрылась, показала название, отсчёт и три быстрых ответа.
- «Увидел» закрыл реальную карточку; после закрытия на экране осталось только меню-барное окно.
- В режиме «Вставлять для проверки» кнопка «Дальше» открыла нужную задачу и оставила в активном ProseMirror точный текст `Дальше`; приложение подтвердило его повторным чтением и закрыло карточку.
- В режиме «Отправлять сразу» кнопка «Дальше» создала новый turn в той же тестовой задаче. Turn завершился ответом `Готов продолжать. Пришлите следующий тест.`
- Уведомление появилось поверх полноэкранного окна Codex размером 1440×900; после теста Codex возвращён в обычный режим.
- Экран настроек, переключение режимов, темы и preview проверены через реальный UI; настройки сохранились после перезапуска.
- Финальные настройки: тёмная тема, маленькая карточка, звук включён, автооткрытие через 15 секунд, режим черновика, автозапуск выключен.

## Исправлено

- Bash 3.2: неоднозначное раскрытие `$ARCH…` заменено на `${ARCH}…`.
- К FSEvents добавлены vnode-наблюдатели файлов и каталогов: записи Codex в уже открытый журнал теперь обнаруживаются без ожидания пакетного FSEvents-события.
- Устаревший `AXUIElementPostKeyboardEvent` заменён на `CGEvent.postToPid`.
- Для текущей macOS-версии Codex, игнорирующей `prompt` у существующей deep link, добавлен ограниченный AX fallback: только активное окно, только ProseMirror, только пустой редактор, обязательное точное повторное чтение.
- Учтён Chromium-placeholder пустого редактора и фокус на кнопке после deep link; окно подтверждения начинается после открытия приложения.
- Кнопка запроса Accessibility показывается в настройках для обоих режимов быстрых ответов.

## Нагрузка

- Покой финальной сборки: 30 912 КБ RSS, 0,0% CPU.
- Раскрытая реальная карточка: 43 920 КБ RSS; мгновенный снимок 9,2% CPU, через секунду 0,6%.
- Наибольший краткий CPU-пик при UI-прогонах: 17,7%.

## Не проверено либо проверено частично

- Кнопка «Открыть» на реальной карточке отдельно не нажималась; открытие нужной задачи подтверждено через оба быстрых ответа.
- Отсчёт автооткрытия отображался, но переход ровно по истечении 15 секунд не доводился до конца — карточки закрывались вручную.
- Фактическая слышимость звука не измерялась.
- Автозапуск не проверялся настоящим выходом и входом в macOS.
- `x86_64` собран, но не запускался на физическом Intel Mac.
- Не проверены несколько мониторов, другие версии macOS и живой сценарий с отозванным Accessibility.

Реальные пользовательские задачи не изменялись; проект никуда не публиковался.
