## Исправления

- Windows: большие строки журналов пропускаются целиком. Раньше обрезанный префикс мог ошибочно стать допустимым событием. Ошибка воспроизведена падающим тестом до исправления.
- Windows: поля только для чтения отклоняются. Ошибка воспроизведена падающим тестом.
- Windows: проверяется принадлежность поля конкретному окну, а не только процессу. Проверен отказ при одинаковом тексте в двух окнах одного процесса.
- Windows: очередь ограничена 200 уведомлениями; при переполнении сохраняется текущая карточка, удаляется самое старое ожидающее уведомление.
- Windows: журнал диагностики ротируется после 1 МБ; сохраняется одна предыдущая копия.
- Обе платформы: разные события без turn_id различаются по времени события, а не схлопываются в одно.
- Обе платформы: неудачное открытие ссылки больше не скрывает уведомление.
- Windows: режим черновика может подтвердить видимый текст через Accessibility, не ожидая файл. На Mac такая проверка используется, если уже дано разрешение Accessibility; без разрешения остаётся проверка файла.
- Windows: после быстрого ответа скрывается неактуальный отсчёт. Высота карточки со статусом сохраняется при сворачивании и разворачивании.
- Mac: старый файл настроек с отсутствующими новыми параметрами дополняется значениями по умолчанию, сохраняя остальные параметры.
- Mac: после запроса отправки есть тайм-аут ожидания начала задачи. Кнопки быстрых ответов блокируются на использованной карточке, чтобы исключить повторную попытку при неопределённом результате.
- Mac: начальные переводы строки считаются изменением текста; допускаются только завершающие переводы строк поля.

## Что ещё требует проверки

1. **Mac:** компиляция с SDK, Accessibility в настоящем Codex, Apple Silicon/Intel, настройки автозапуска и полноэкранные пространства. Проверка синтаксиса не подтверждает доступность API и правильность типов.
2. **Несохранённый черновик:** перед вставкой проверяется файл состояния Codex. Он может отставать от интерфейса — именно это уже наблюдалось при подтверждении вставки. Поэтому сохранность ещё не записанного черновика нельзя гарантировать. Нужно отдельно проверить поведение deep link при существующем тексте на обеих платформах.
3. **Принадлежность задаче:** проверяется ссылка назначения, приложение, окно и точный текст. Это не независимое подтверждение ID открытой задачи непосредственно из редактора. Одновременное переключение задач самим Codex остаётся непроверенным случаем.
4. **Зависший интерфейс Codex:** Windows UI Automation вызывается синхронно; зависший провайдер доступности способен задержать интерфейс уведомителя. Для строгой изоляции потребуется отдельный процесс с тайм-аутом. На Mac AX-запросы имеют тайм-аут и выполняются в фоновой очереди.
5. Длительная нагрузка, сон/пробуждение, удаление корня журналов во время работы, несколько экранов с разным DPI и изменения внутренних форматов Codex ещё не прошли сквозные испытания.

Эти ограничения не замаскированы успешными модульными тестами. Автоотправка остаётся зависимой от интерфейса и недокументированных ссылок Codex.

## Повторная проверка

Windows: `powershell -File .\verify.ps1` из папки Windows-проекта. Скрипт собирает отдельные тестовые EXE, проверяет код завершения и результат; останавливает тест через 30 секунд. Тесты не отправляют сообщения в Codex и не меняют автозапуск.

Mac: `bash Build.command`. Скрипт собирает обе архитектуры и выполняет встроенные проверки на текущем Mac. После сборки вручную проверить оба режима ответа в безобидной тестовой задаче, смену фокуса и уже заполненное поле.
